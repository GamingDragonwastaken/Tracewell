# Tracewell

Local evidence consistency and provenance engine for consequential applications.

**Start here:** [read the engineering case study](CASE-STUDY.md), then use the
local walkthrough below. Every bundled document and packet is synthetic.

Tracewell turns synthetic documents into a source-linked evidence graph, detects contradictions and expiry, and routes uncertainty to a human review queue.

## What the demo proves

- Every displayed field links to a source span or is labelled unresolved.
- Contradictions are generated by deterministic, versioned rules.
- Expired evidence remains visible and cannot silently verify.
- Review decisions are recorded in an append-only decision log.
- Exports include a manifest and hashes that can be verified independently.

## Explicit limits

Tracewell uses synthetic fixtures only. It does not approve real immigration, financial, medical, legal, credit, or customer cases and has no hosted identity or regulatory certification.

## Reviewer path

1. Open the seeded contradictory case.
2. Select a finding and inspect both source spans.
3. Resolve one field, reject another, and request more evidence for a third.
4. Open the decision log.
5. Export and verify the redacted evidence bundle.

## 90-second reviewer walkthrough

1. Run `npm.cmd test`, then start the workspace with `npm.cmd run dev`.
2. Open `http://127.0.0.1:4174/` and choose **Northline Systems / ownership
   packet**.
3. Inspect the conflicting beneficial-owner observations and their two source
   spans. A reviewer must select one of those linked sources before the case can
   verify.
4. Switch to the expired-certificate packet. Acceptance is refused until fresh
   evidence replaces it; the case remains `EXPIRED`.
5. Open the append-only review log, then export the redacted bundle and its
   manifest.

## Run locally

```powershell
npm.cmd test
npm.cmd run dev
```

Open `http://127.0.0.1:4174/`. The server is dependency-free and starts with three synthetic case packets: a contradictory ownership case, a clean verified case, and an expired certificate case. Import a packet from `fixtures/custom-case.json` or paste your own JSON, validate it against the packet contract, save it to local storage, reconcile it, inspect the evidence graph, record a reviewer decision, and export a redacted JSON bundle.

## Verification boundary

The usable local product has two explicit layers: a browser-native evidence workspace for repeated review and a dependency-free Node reconciliation kernel that can be imported into tests or a future service. The React/Fastify/SQLite adapters described in `TRD.md` remain a deployment option; they are not hidden dependencies of this local product. Every packet is synthetic and stays in the browser unless the operator exports it.
